# 新睿操作参考

这些是 2026-10-24 探索观察到的方法，运行时以当前画面为准；坐标、具体牌面和赛事日期都是运行输入。

## App 与赛事

使用 `mcp__cua_repl`，先按该工具当前说明初始化。可尝试 `cua.getApp("com.xinruibridge.bridge")` 或 `cua.getApp("新睿桥牌")`。未运行时可用实际安装路径 `/Applications/新睿桥牌.app` 打开。

安装壳和运行 wrapper 可能共享 bundle ID：若定位失败／报重复，读取当前 `cua.listApps()` 或工具错误给出的实例列表，选**当前运行实例**路径重新 `getApp`。即使首次安装路径调用报告未找到 running app，也先看新清单，壳可能已经启动。运行路径来自本次工具结果，不能缓存 `/var/folders/...`。内层 `Wrapper/XRBridge-mobile.app` 曾因 executable format 不能直接启动；使用正常安装壳。无需新建 app discovery 工具。

以新鲜 AX 状态和截图确认选中“新睿桥牌”，完成现有账号正常登录；缺少登录／验证条件则保存并报告。可见广告才点其关闭／跳过。大厅有部分 AX 控件，牌桌常只有通用 text entry，需视觉读牌。

找到当前**每日MP赛**，核对平台赛事标题、日期、已完成进度及未完成牌。探索时服务器每赛 12 副，日程只完成绑定的一副。纽约日期可能与平台赛事日期不同。进入已有未完成牌优先；进入前后记录实际进度，不能把大厅旧进度当新牌依据。

## 叫牌与出牌

探索叫牌板有“普通 → 放大 → 解释 → 再点提交”的状态；不同界面可能直接提交。先根据当前显示辨别预览和确认，记录叫品解释的点力／牌型／逼叫含义。解释与实际牌面不一致时两者照实分别保留。

出牌可能先点花色，再选具体牌；布局随持牌数变化。每次从当前截图定位，操作后确认座位、牌和手牌减少。工具提示 app 已变化时重新取完整状态，不能盲目重复点击。

牌按 `S/H/D/C`，A K Q J T 9…2 记录；横置 6/9 等可用现有图像裁切／旋转复核。13 张、去重、HCP 检查只能发现部分错误，仍须对照牌面。

第四手可能在下一次观察前被收走。打开历史／上一墩面板可恢复上一墩四张真实牌及叫牌；收起面板后桌面显示**当前墩**。上一墩和当前墩不同是正常时间差。标注面板所对应墩号、首家及顺序，把新看到的牌追加到正确位置。

## Claim 与结果

Claim 对话框先核对“申请的剩余墩数”和显示的定约结果，默认值不能直接接受。平台可以拒绝；拒绝／取消后回到当前桌面核对同副继续打。

接受 claim 后还要读取服务器的实际本副结果、单副分数／百分比／排名、赛事进度。结果延迟时留在当前结果路径刷新观察；不要用“开始打牌”试探更新。

本副比较页可看各定约／得分分组、代表桌完整牌局、叫牌和逐墩回放。只把确实打开并核对的部分记成观察。双明手表需要确认行列是座位、花色和“定约阶数”还是“墩数”；例如 4S 可能表示能做四黑桃，即十墩，不能直接记四墩。看不清的表头保留未知。
