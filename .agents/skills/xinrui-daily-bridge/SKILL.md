# 新睿每日单副

使用 `mcp__cua_repl` 观察和操作新睿；使用 Bridge Coup 的 `bridge-external` 持续调用生产做庄 Expert。每次只绑定一副，完成记录与两类总结后退出。叫牌、防守、claim 和总结暂由外层 Codex 判断，记录真实来源。

## 绑定本次任务

先读 [每日配置](references/daily-task.md)，取得可持续使用的 Bridge Coup checkout、Codex runtime 和记录目录。缺少必要配置或桌面不可操作时，保存原因并报告未完成。正常登录、权限及账号由现有环境提供。

查看记录目录中的最近记录，再观察实际赛事。按**账号可辨识标签、赛事名称／平台日期、牌号**绑定，不以纽约日期代替新睿赛事日期。为新副生成一次 UUID 作为 Expert `boardID`，把映射保存在记录；接续时沿用。

- 有绑定牌的未完成记录：先核对同一副，按下文接续；不以新副代替。
- 本赛事本轮每日单副已完成：核对平台进度并返回原记录，不再开始下一副。不要因为结果延迟或重复唤起再开牌。
- 用户已手动推进：尊重当前平台进度。若遇到正在进行的牌，只有公开历史可核对才接续；无法确定与原记录的关系就保存并停止。不同日的新赛事可以绑定新副；跨日仍有未完成牌时先处理原副。用户另行明确授权的新一副手动验收，可绑定平台当前下一副；既有探索完成记录不授权重打旧副，也不扩展日程范围。
- 另一个运行仍在处理绑定牌：不并发操作，保留现状并报告。只在当前运行确认取得同副控制后行动。

首次绑定时复制 [中文记录模板](assets/board-record.md) 到仓库外，默认 `~/Documents/xinrui-daily-bridge/`，文件名含本地时间和牌号，避免覆盖。附件放同名 `-assets/`；记录实际路径、时间及时区。绑定、叫牌、每次实际动作、关键计划、claim 和结果随进展保存；不是等终局才写。

## 观察、叫牌和角色

打开 app 和操作前读 [新睿操作](references/xinrui.md)。从当前截图定位，观察后才操作。每个动作后重新读取实际状态；建议、预览、点击、动画均不是成功事实。看不清时用现有截图／历史面板复核，仍不确定则保存未完成。

确认赛事、平台日期、牌号、进度、发牌人、局况、我方座位、计分及体系；按花色记初始牌、核对 13 张唯一牌和 HCP。完整记录轮到各座位的叫牌、pass／double／redouble、alert 与公开解释。外层 Codex 依据可见手牌、实际叫牌和体系叫牌；先分辨预览与提交，再确认实际叫品。选择与理由标记 `outer-codex`。全 pass 时直接确认平台的流局结果，Expert 标记未触发。

开打后记录最终定约、庄家、倍数、明手、首攻和正式目标。MP 目标考虑超墩，实际目标与分析指标分开。庄家是 decision controller，从明手出牌时 acting seat 仍是明手。

- **我方或对家做庄**：庄家与明手的常规选择都经生产 Expert。只把庄家及已曝光明手的初始牌、完整实际公开牌序、定约、局况、计分、目标及公开叫牌／解释交给入口；对手暗牌保持未知。读 [Expert 调用](references/expert.md)，保留同一进程。
- **我方防守**：外层 Codex 只控制用户授权座位，以本手、明手及公开事实决策；对家和对手由新睿控制。标记 `outer-codex` 与 `platform`，不冒称使用了防守 Expert。

## 建议、执行、确认

维护实际公开牌序、当前墩、已完成墩的赢家、累计墩数、两手余牌及缺门。事实与推断分开；历史面板的上一墩不覆盖当前墩。自动行动也按实际顺序记录，不从计划推演牌序。

做庄循环：`observe` 新的真实平台牌 → `decide` → 按返回的座位／牌操作 → 重新观察该牌确实打出 → 带当前 authorization `observe` → 保存。平台在请求建议前已自动打出的唯一合法受控牌，按 [Expert 调用](references/expert.md) 的 `automatic: true` 分支确认并记 forced；不虚构建议。首次实际 Expert 选择建立计划，所有有选择行动通过生产 Expert；手动 forced 建议仍带入口授权确认。外层不能因不同意建议而换牌或把公开计划编译成跳过 Expert 的执行策略。

记录 advice、authorization、实际确认之间的关联，以及 decision 文件、公开计划变化、真实 reviewer verdict 和 executionDisposition。`contested` 是既有政策下的执行授权，不能写成 approve。生产 player 和独立 reviewer 沿用既有配置；外层聊天模型设置不改变它们。入口失败时保存已有 evidence 和状态，不绕过 review 或重启规避限额。

## Claim 与终局

Claim 由外层 Codex 判断：写明当前双方已得墩、剩余墩、申请墩数及从决策时信息可证明的路线，同时检查可争取的超墩。不确定则继续出牌。核对界面申请数和对应结果后提交，保留 Expert 进程直到平台确认终局。

- 接受：记录实际接受和服务器最终结果；真实牌序到实际最后一张为止，claim 分配的余墩另记。
- 拒绝或取消：记录结果，重新观察同副当前状态；把新增实际牌按序交给入口，继续正常打牌。尚无终局时不 `stop` 入口，不重发旧点击。
- 结果尚未更新：等待并重新读取同副结果／赛事进度，不点击“开始打牌”来刷新，不进入下一副。

全打完、claim 接受和全 pass 都以平台结果确认完成；保存证据。只做完操作却没确认结果，状态仍为未完成。

## 比较、总结和交付

终局后读实际可用的同牌比较、代表桌回放和双明手分析；全牌此时才可读入赛后分析。记录选了哪桌、看到了哪一墩／哪段叫牌及结果；数据不可用则写不可用。全牌可得时核对四家各 13 张、共 52 张唯一牌。单副分数／MP／排名与整场指标分别记录并说明视角。

完成模板中的两类总结：

- **打法总结**：公开计划与转折、可疑选择和可执行替代；分清当时事实／推断、赛后暗牌／DD、对手帮助和运气、尚未确定的因果。不同首攻或叫牌的高分桌不能直接证明本桌选择错了。好成绩与 review 通过都不证明棋力。
- **流程总结**：具体读牌、重复观察、失败点击、app 定位、接口请求、claim、结果延迟等摩擦及临时处理；记录原始证据位置、实际耗时、实际打出的完整墩／未完墩和 claim 数。后续工具／知识／评测候选只记候选，不自动改代码或配置。

读回已保存 Markdown 和所引用的本地材料，核对绑定、牌序、来源、结果、总结、未确认信息及接续状态。成功后 `stop` Expert，退出新睿并从 app 状态确认已退出，更新记录。异常时保留牌局及材料，记录 app／进程实际状态，避免通过放弃牌局强行收尾。向用户返回完成／未完成、关键结果、一条发现和可打开的绝对路径记录链接。

## 基本接续

先读最新记录和其引用的最新 `continuation.json`，再观察同一赛事／牌号、当前墩与历史墩、已打牌、余牌及平台结果。逐项核对后才继续。

原进程仍在、健康且状态匹配时延续它；若有当前有效待执行建议，仍按其 authorization 执行并观察确认。此时 checkpoint 的 unsafe 只禁止重建，并不自行撤销原进程有效授权。需要新会话时，只有最新 checkpoint `safeToResume: true` 且 configuration 与实际核对完全一致，才能按 [Expert 调用](references/expert.md) `resume`。记录新会话重建及证据链；不恢复旧 thread、点击、坐标或 authorization，不回退更早的 safe 文件来覆盖最新 unsafe 状态。新增实际事件按序输入。

缺少初始可见手牌／真实完整历史、待确认建议无法消歧、需要重建但最新 checkpoint unsafe、平台已换副、入口失败／超限等情况，保存最后确认事实、缺口、附件与 app 状态，报告未完成；不猜补事实、不默默开启另一副。入口保留既有单请求和整副限额，接续不能重置绝对截止时间。
