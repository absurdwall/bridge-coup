# Ticket 51: bounded recovery and reviewed outcome evidence

Runtime recovery and evidence are implemented through the production Expert/BoardDriver seam. No live model request or frozen acceptance cycle was made for this ticket. Instructions retain the independently reviewed ticket-50 hashes (player 7216835b26ad7b9aa8c00fb9870d1c7a95837953059927623c1d6800efbebf90; reviewer 6abfef19977a81a426a48afe12430e7bcc9f7170faef43a298d8313b6dbc9b37).

- A reviewer candidate gets at most four technical attempts. All retries retain its exact frozen position, candidate ID, proposal and proposed plan. A valid approve/revise/uncertain ends the technical loop immediately; only valid judgments consume semantic rounds. Transport/protocol exhaustion stops without execution or contested fallback. Player failure, invalid proposal, identity/state mismatch and session loss remain fatal; the player is never silently restarted.
- Each request is capped at 180 seconds or the smaller configured/remaining board allowance. The same absolute automatic board deadline covers both roles, revisions, retries and processing, up to 1,800 seconds. Execution authorization is also rechecked at commit. A one-shot continuation race returns on deadline even if the transport ignores cancellation; superseded completions only enter evidence and cannot execute or adopt a plan. Native process protection remains enabled.
- Missing required public facts suspend the same in-process Expert rather than ending its player session. Completion can add missing facts at the identical position while preserving known history, hands, configuration, prior plan and DecisionSession. Conflicting or altered facts fail. Explicit human waiting is recorded separately and excluded from BoardDriver automatic runtime. Complete frozen canonical snapshots cannot lose facts partway through their immutable review loop; the recoverable missing-fact gate is therefore before a new candidate, with zero new semantic rounds. Prior player thread, prior accepted plan and evidence survive that gate. General process-restart recovery is not implemented.
- Every role attempt has input/instructions/schema, request/decision/candidate association, semantic round, technical attempt, public raw output when observed, identity, elapsed time, outcome and observed usage. Failed attempts and later completions remain distinguishable. Native failures preserve available partial public output and identities; unmatched native completions are sanitized and retained. Missing usage is unknown, never zero. Native tokenUsage.last is retained as reported per-turn usage, not cumulative thread totals; the inspected installed protocol definition is saved under protocol/.
- New JSON already uses readable UTF-8 in the current serializer. A native runtime/loopback-provider regression verifies actual request bytes contain Chinese/non-BMP text and that parsed snapshot values preserve literal backslash-u text, controls, quotes and backslashes. No historical payload is rewritten and no replacement serializer was needed.

Evidence interfaces for evaluation: ExpertSession.requestEvidence() exposes the current journal, including late arrivals after a caller timed out. DecisionRecord.requestEvidence is the current-decision snapshot at authorization; DriverTrace.requestEvidence covers all observed board attempts. Count request attempts by excluding outcome `late`, which is an additional observation for an existing UUID. DriverTrace.modelRequests/playerRequests count actual player attempts, including revisions; reviewerRequests, semanticReviews and retries are separate. ExpertFailure.requestEvidence and the CLI failure JSON preserve failure-path attempts and reviewRounds. DecisionRecord.input is the actual final player input, while canonicalInput remains the original full snapshot.
