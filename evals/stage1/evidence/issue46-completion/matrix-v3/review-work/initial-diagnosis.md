## Concrete order mismatch and hypothesis

`Sources/BridgeExpert/Resources/DeclarerInstructions.txt:8-29` says to establish facts, form/check the plan, then choose the current card and explain it. But its `OUTPUT FORMAT` list at lines 31-38 orders fields `publicReason`, `selectedCard`, `plan`. `Sources/BridgeExpert/Expert.swift:250-258` explicitly orders structured generation as `publicReason`, `plan`, `selectedCard` with the comment “ground the current reason before future advice.” The actual captured schema order is `publicReason`, `plan`, `selectedCard`. Thus the model is asked to decide/check the plan before the current choice, but is serially cued to write a current-action explanation first, then the plan, then the card. JSON object key order has no semantic validation effect, but the implementation deliberately uses this property order for structured generation, so the cue is real.

A legitimate next-candidate experiment is to align the property order and output-format examples with the decision process, e.g. `plan`, `selectedCard`, `publicReason`, while retaining exactly the same three output fields and all action/plan validation. This may reduce local-choice anchoring; it is an unproven hypothesis. It is especially plausible for decision 5’s reason (“Lead C4 toward dummy’s CQ…”) immediately preceding a plan that repeats the same mistaken finesse story. It does not explain the seven-plus-one arithmetic with confidence and would not be a deterministic safeguard for either arithmetic or card ranks.

If desired, a narrow instruction-only clarification could also state the general target `6 + contract level`, subtract tricks already won, and explicitly reconcile the count before describing “the ninth.” That is not evidence of a defective snapshot: the 3NT level, tricks won and objective are all already supplied, and instructions already require reconciliation. Treat it as another prompt hypothesis, not a missing-data repair. Do not add output fields, solver/second-reasoner calls, answer repair, fixture-specific exceptions, or a waiver of these failures.
