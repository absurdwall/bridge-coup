# 07: 完成实际 Mac 应用的整体验收

**What to build:** 用户能够在实际构建的 Mac 应用里完成从真实截图到教学、关键出牌、双明手核验和保存恢复的完整复盘，获得有依据的第一版验收结果。

**Blocked by:** 04：核验完整牌面的双明手结果；05：分析关键出牌节点；06：保存并继续一份复盘

**Status:** in-progress

- [x] 用实际可启动的 Mac 应用验收，记录构建版本及启动路径；浏览器原型或模拟检查不能替代。
- [ ] 走通真实截图导入、识别核对、补回遗漏 A、生成做庄计划、追问、修正后重新分析的流程。
- [x] 使用不完整材料确认必要追问与条件分析正常，既不强行补全未知牌，也不因不能求解而阻止教学。
- [x] 对完整局面执行真实 DDS 并核对已知结果，实际演示一次关键出牌分析；教学与事后核验保持区分。
- [ ] 检查跨功能的信息隔离，包括全牌截图、求解后继续教学、修正与重新打开；旧回答或后台响应不能泄漏隐藏信息或覆盖新版本。
- [x] 保存并重新打开含两种教学模式及 DDS 结果的复盘，确认牌面、对话、结果来源、信息版本及过期状态保持一致。
- [x] 用小规模记录牌例评估真实教学是否使用正确牌面、给出自洽路线、尊重 IMP 取舍及不确定性，并解释一项本局关键基础技巧；记录实际问题。
- [x] 检查正常 Mac 窗口内 A 的左右布局、牌张和长讲解可读，核对、模式与追问入口可用。
- [x] 记录识别、模型、求解器失败时的保留/重试行为；未验证的失败类型单独列出，不推断为已通过。
- [x] 分别报告确定性流程检查、真实 DDS 数值、真实模型教学质量、实际 Mac 验收四类证据；任何必需项未满足时记录缺口，不宣称全量完成。

## Notes

这是已完成纵向功能的跨功能验收，不替代每张票自己的测试，也不是把全部测试推迟到最后。修复范围限于已批准第一版。

实际记录见 [验收证据](../evidence/07-mac-acceptance.md)。真实截图到计划的闭环及完整截图场景的跨功能隔离仍未验收；当前只完成截图识别候选验证，不能据此标记整票完成。
