# 01: 在 Mac 中获得第一份真实做庄计划

**What to build:** 用户在可启动的 Mac 应用中看到 A「并排工作台」，手动确认可见手牌、分析视角和必要定约背景，点击按钮后通过官方 Codex runtime 获得真实中文做庄计划。这个最小完整流程同时验证订阅登录接入是否实际可用。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 选定并记录最小 Mac 技术栈、实际可用的 Codex runtime 版本及启动方式；提供可实际打开的应用，不仅是浏览器中的原型。
- [ ] 保持用户已选定的 A 版浅色布局：左侧牌面与核对入口，右侧教学。原型作为视觉来源，不直接搬入固定示例文案或 B/C 切换器。
- [ ] 允许手动提供两手可见手牌、座位、定约、首攻和当前问题需要的信息；未知手牌保持未知，明显重复牌或矛盾信息有提示。
- [ ] 通过官方支持的 ChatGPT 登录路径获得真实模型响应；不提取订阅 token 充当通用 API key，不将假响应展示为已接通。
- [ ] 默认中文、IMP；点击生成后呈现具体做庄计划、关键理由与必要假设，尊重用户的非基础水平。
- [ ] 从第一份计划起就采用独立的决策时信息视图，教学请求不夹带隐藏牌、未来出牌或识别会话；自动化检查可观察外部请求边界。
- [ ] 运行时未安装、登录不可用、额度受限或请求失败时，明确显示原因并保留输入，允许重试；真实接入未验证时不将本票标记完成。
- [ ] 在主要复盘流程边界验证手动输入到结果/失败恢复的外部行为，并在实际 Mac 应用中记录一次真实计划的演示证据；不以固定措辞断言生成质量。

## Notes

本票只要求手动牌面到一次真实教学的最小路径；截图识别、持续追问、DDS 与持久化由后续 tickets 交付。若首选接入路径不可用，记录具体证据与替代建议，不静默改成 API 付费方案。
