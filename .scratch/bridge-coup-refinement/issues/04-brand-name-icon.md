# 04: Bridge Coup 名称、选定图标与独立字标落地

**What to build:** 用户在 Finder、Dock 和应用界面看到一致的 Bridge Coup 名称、选定叠牌图标及独立图片字标，同时继续使用已有保存数据和登录接入。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 从 spec 引用的原型交接材料取得并归档用户最后选定的叠牌原图和独立图片字标，使构建不依赖临时 worktree 或生成缓存；记录准确来源。
- [ ] 使用已选择的叠牌图原图构图及原配色；不替换为旧 BC 标志，不重新生成 Logo，不做浅蓝改色，不强加 BC 字母。
- [ ] 将牌图制作为有效 Mac 图标资源，大小尺寸可读、透明边缘正常；Dock 图标不合入长文字。
- [ ] 应用界面独立使用已认可的图片字标，不用系统字体近似替代；在可读尺寸下与牌图协调放置。
- [ ] 应用可见名、相关窗口/菜单和分发说明统一 Bridge Coup；保存稳定标识和数据位置，必要的兼容处理须明确验证。
- [ ] 旧复盘能在更新后打开，已有支持的登录/连接仍可使用；不能因改名无提示地变成空库。
- [ ] 构建并从 Finder 启动实际 app，核对 Finder/Dock 图标、名称、字标及旧数据；源文件存在不能代替打包后的检查。

## Context and scope

图标选择已完成，不重新访谈。详细资产出处见父级 spec 的 Further Notes；原型 handoff 包含按时间追加的历史，以最后选定叠牌图的结论为准。仓库迁移不属于本票。

阅读父级 spec 和已有项目文档，沿用当前生产实现。若任务使用隔离 worktree，先核对源项目最新已提交实现是否已包含，避免从过期快照另起应用；保护用户未提交工作，不顺手处理仓库迁移或其他 tickets。
