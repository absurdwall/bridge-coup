# 01: 模型与 effort 选择、保存偏好并用于真实请求

**What to build:** 用户在现有 Mac 应用的 Codex 连接设置中选择模型和 thinking effort，默认 Luna + Medium；保存偏好并让后续真实识别、教学及追问请求采用明确的有效配置。保留当前认证方式和复盘能力。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 首次设置为 Luna + Medium；展示 Luna、Sol、Astra 对应的实际运行时标识与可用性。根据真实运行时能力核实可用模型/effort，不将原型示意矩阵写成已验证支持列表。
- [ ] 可选 effort 为运行时支持与产品规则的交集：排除 Ultra，Max 只允许 Luna。初始 Luna 或 Medium 不可用时明确提示并呈现有效选择，不静默发送非法或用户不可见的替代配置。
- [ ] 切换模型时保留仍合法的 effort；否则优先回退到受支持的 Medium，再考虑运行时默认，并明确展示变化。无有效组合时阻止提交并说明原因。
- [ ] 记住上次有效模型/effort，退出后重新打开可恢复；恢复时重新检查可用性，不清空既有牌局与对话。
- [ ] 在真实模型请求边界使用当前选择，包括可适用的截图识别、教学和追问；不支持某输入能力时给出明确说明，不以控件显示代替实际配置生效。
- [ ] 提交时固定本次请求的模型和 effort；运行中改变设置只影响后续请求。结果保留足以识别其使用配置的来源信息。
- [ ] 连接设置有清楚、紧凑的入口并符合 A 版工作台；不改现有认证生命周期，不读取或输出凭证。
- [ ] 在已约定的复盘工作流及外部请求边界测试默认、保存恢复、能力过滤、切换回退、不可用状态和运行中更改，不测试内部方法细节。
- [ ] 在实际 Mac 应用操作设置并完成至少一次真实请求，记录实际模型/effort 及可用性证据；模拟检查和真实验证分开报告，阻塞时不声称全量验收通过。

## Context and scope

只实现本票。遵循用户调用的 implement 流程：在约定边界尽可能 TDD，完成后 code-review 并提交当前工作分支。后续定约、牌桌编辑、品牌和整体精修不在本票中。模型标识/能力以目标 runtime 为准；不要把 Codex 宿主任务的模型菜单当成应用集成已支持的证据。

阅读父级 spec 和已有项目文档，沿用当前生产实现。若任务使用隔离 worktree，先核对源项目最新已提交实现是否已包含，避免从过期快照另起应用；保护用户未提交工作，不顺手处理仓库迁移或其他 tickets。
