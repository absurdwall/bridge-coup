# Bridge Coup：自主推演、双明手牌桌与模型连接改进

状态：需求、原型方向及测试边界已获用户确认，2026-10-02。发布至 `absurdwall/bridge-coup`，标记 `ready-for-agent`。尚未实施产品改动。

## Problem Statement

用户打开应用后无法方便地找回 Codex Runtime；文件选择器要求用户自行寻找可执行文件，却没有搜索入口和路径建议。模型列表及人为收紧的 Thinking Effort 限制了用户比较新版模型与 Astra Ultra 的效果。

导入的手牌没有直接复用于事后双明手检验，用户不得不重复输入。当前牌桌主要用于录牌，不能自然地控制四家出牌并尝试不同打法。用户需要在牌桌上直接看到每张合法出牌的双明手结果，并另外查看原始完整牌局在各庄位、各花色下的最高可成定约。

## Solution

保留现有四家围桌、品牌、双栏教学工作区和轻量设置入口，采用本轮已确认的 A 角落叫牌小表。手牌以接近现有原生应用的连续牌点呈现；关闭逐牌结果时不使用宽大独立牌片，开启结果时仅增加标签所需的空间。

导入和核对后的原始四手成为共享牌面。用户录齐有效四手并明确庄家、定约后，点击“开始自主推演”，自行控制四家合法出牌。桌心展示当前墩，牌区展示剩余牌；教学可见性仍由四家勾选独立控制。

“逐牌结果”开关控制当前行动家各张合法牌上的双明手标记。独立“原始四手定约表”回答开局时各庄位、各花色的最高可成定约，不随推演变化。改善 Runtime 自动发现和手动恢复，并提供 6 Luna、6.1 Sol、6 Astra 及各自 Runtime 实际支持的完整 Thinking Effort。

## User Stories

1. As an 应用用户, I want 打开应用时自动寻找可用 Codex Runtime, so that 我不用每次寻找可执行文件。
2. As an 应用用户, I want 手动重新搜索 Runtime 的入口, so that 安装或更新后能恢复连接。
3. As an 应用用户, I want 搜索失败时看到具体建议路径并能复制或定位, so that 我知道该去哪里选择文件。
4. As an 应用用户, I want 继续手动选择 Runtime, so that 非标准安装位置也能使用。
5. As an 应用用户, I want 已保存路径失效后仍能搜索其他位置, so that 更新软件不会把我困在失效配置中。
6. As an 应用用户, I want 区分未找到 Runtime、Runtime 无法运行和未登录, so that 我能采取对应的恢复操作。
7. As an 模型测试者, I want 在 6 Luna、6.1 Sol、6 Astra 中选择, so that 我能比较本轮指定模型。
8. As an 模型测试者, I want 列表移除旧 6 Sol, so that 不会误选被替代版本。
9. As an 模型测试者, I want 选择各模型实际支持的全部 Thinking Effort, so that 我可以测试 Astra Ultra 等组合。
10. As an 模型测试者, I want 能力不可用时得到明确反馈, so that 应用不会悄悄换成另一个模型或档位。
11. As an 模型测试者, I want 实际教学请求使用所选模型和 effort, so that 比较结果有可信依据。
12. As an 模型测试者, I want 请求开始后保持该次配置且后续选择作用于下一次请求, so that 运行中的结果身份不混乱。
13. As an 学习者, I want 导入并核对一次手牌即可用于牌桌与双明手, so that 不用重复输入。
14. As an 学习者, I want 原始四手和推演中的剩余牌明确区分, so that 出牌不会破坏原始牌局。
15. As an 学习者, I want 教学继续只使用勾选的手牌, so that 完整录入不会自动泄露暗手给教学。
16. As an 学习者, I want 勾选四家进行四明手教学, so that 可以主动选择完整信息分析。
17. As an 学习者, I want 只有部分手牌时仍可使用现有教学, so that 新增推演资格限制不阻碍原有学习方式。
18. As an 学习者, I want 未录齐或存在重复错牌时明确知道为何不能推演, so that 可以修正输入。
19. As an 学习者, I want 通过明确的开始按钮进入自主推演, so that 录牌与出牌操作不会混淆。
20. As an 学习者, I want 自行控制四家的出牌, so that 能探索我想比较的路线。
21. As an 学习者, I want 只允许当前行动家点合法牌并遵守跟牌, so that 推演保持有效局面。
22. As an 学习者, I want 已出牌从手牌移到中央对应座位, so that 能直观看清当前墩。
23. As an 学习者, I want 看见当前行动家、墩数与双方赢墩, so that 不必自己维护局面记录。
24. As an 学习者, I want 每墩结束后正确确定赢家及下一墩首引, so that 推演可以连续进行。
25. As an 学习者, I want 完成整副牌后停止出牌并显示实际推演结果, so that 不会将实际结果混同于最佳打法预测。
26. As an 学习者, I want 开关逐牌双明手结果, so that 可以先思考再查看答案。
27. As an 学习者, I want 每张合法牌直接显示其对应的定约结果, so that 不需要进入第二层比较页面。
28. As an 学习者, I want 逐牌结果随当前局面更新, so that 标签反映此刻的选择。
29. As an 学习者, I want 计算中或失败时不显示过期答案, so that 不会把其他局面的结果当作当前建议。
30. As an 学习者, I want 防守方出牌时标签仍按同一个庄家定约解释, so that 正负号含义不会随行动家翻转。
31. As an 学习者, I want 独立打开原始四手定约表, so that 查看牌局整体定约潜力。
32. As an 学习者, I want 定约表按 ♠、♥、♦、♣、NT 行和北、南、东、西列排列, so that 容易比较花色和庄位。
33. As an 学习者, I want 单元格显示 `5D`、`4D` 等完整定约或 `—`, so that 不用自行把赢墩换算为阶数。
34. As an 学习者, I want 原始定约表不会随推演重新计算或变化, so that 始终能回看同一副原始牌的潜力。
35. As an 学习者, I want 修改原始牌面后旧结果失效, so that 不会使用错牌版本的结论。
36. As an 学习者, I want 叫牌记录在角落小表中保持可查并可展开, so that 桌心可以用于出牌而叫牌背景仍可访问。
37. As an 学习者, I want 紧凑连续牌点在小窗口也清晰可点, so that 不需要为宽大牌片占用过多空间。
38. As an 学习者, I want 四家区域保持均衡且结果标签与对应牌明确关联, so that 不会误读或误点。
39. As an 学习者, I want 撤销、重做和从原始局面重走来比较路线, so that 不用反复重新录牌。（建议默认行为，见下文。）
40. As an 现有用户, I want 旧保存记录仍能打开且原始内容不被覆盖, so that 本轮升级不损坏已有学习材料。

## Implementation Decisions

- **确认范围**：六项需求以本轮 grill 为依据；视觉基线以最终原型评审为依据。本轮 A 指角落叫牌小表，不替换此前已接受的整体四家牌桌方向。原型中的 144 px 是密度参考，不是原生布局固定像素要求。
- **共享牌面与当前局面**：在现有牌局工作流和应用协调层中维护一份原始手牌事实及其版本；推演维护从原始事实派生的剩余牌、当前墩、行动家、已赢墩及出牌序列。双明手入口不再要求重填同一份手牌。复用既有牌面解析、校验和可见性语义。
- **启动资格**：有效四手为每家 13 张、合计 52 张、无重复或未知牌；缺门与未知仍有区别。推演还需要有效庄家和定约，首攻方由庄家确定；叫牌历史不要求补齐。若已有首攻输入，必须校验所属座位及牌面并在开始时明确呈现，不能悄悄忽略或重复出牌。
- **推演规则**：按合法轮次与跟牌规则推进，正确判断将牌、无将与赢家。全程由用户控制，不自动替其他玩家选牌。出完 13 墩后进入结束状态。
- **建议默认操作（规格作者建议，不冒称逐项获得用户确认）**：沿用原型四张出齐后手动收墩，让用户看清这一墩；之后由赢家首引。撤销恢复上一个操作前的整个局面，重做恢复被撤销操作；分叉新出牌清除旧重做分支；重走回到同一份原始牌局的起点。实际落地可做不改变这些可观察行为的细节调整，无需重新比较整体布局。
- **修改输入**：编辑原始手牌后旧推演与相关 DDS 结果不可继续使用；存在推演进度时明确说明会重置，保留取消途径。改变庄家或定约需重新开始该推演；原始四手定约表只依赖原始牌面，不因选中定约、可见性勾选或出牌而失效。
- **教学信息边界**：复用现有教学请求构建入口，投影用户勾选的手牌与相应已知信息。DDS 完整暗手、逐牌标签和定约表不可自动注入教学；四家全勾选时允许完整手牌教学。局面改变后已有分析不得冒充当前局面新生成的结论。
- **逐牌求解**：复用现有双明手求解接口与结果转换，给当前行动家每张合法牌完整映射结果，包括求解器合并的等价牌。`=` 为恰好完成所选定约，负数为宕墩，正数为超墩；统一从庄家定约视角解释。开关关闭隐藏标签；打开后按局面版本刷新，旧异步结果不能覆盖新局面。失败提供可重试状态，不编造结果。
- **独立定约表**：由真实本地 DDS 计算 5 × 4 组合，庄位不同需使用正确首攻方；最高可成阶数为最佳可得总墩减六，小于一则显示 `—`。同一原始牌面版本首次请求计算后复用结果，不在每次出牌或打开视图时重复求解。不能以当前局面逐牌结果冒充完整定约表。
- **Runtime**：扩展既有发现流程，保留手动选择、保存路径、PATH 和既有常见安装来源，增加当前桌面应用内嵌运行时等常见来源。候选需检查可执行性及协议可用性；失败继续查找。重试搜索不抹掉可工作的手动配置。路径提示基于实际发现结果与明确标记的候选，不保证某路径一定存在；使用已有账号登录流程，不读取或搬运账号凭据。
- **模型目录**：产品目标为 `gpt-6-luna`、`gpt-6.1-sol`、`gpt-6-astra`；实际能力以已连接 Runtime 目录为准。取消人为禁止 Ultra 和限制其他模型 Max 的规则，只展示实际支持档位。模型缺失需明确说明并允许刷新，不虚构支持能力。旧 Sol 偏好迁移到可用的新 Sol，并明确展示当前选择；不可静默发往旧 Sol 或其他模型。请求使用开始时的配置快照。
- **兼容性**：沿用现有保存/打开工作流，兼容历史记录；若旧记录包含与主牌面冲突的独立 DDS 输入，不静默合并或覆盖，应提示核对。新增推演状态若写入记录，须采用可向后读取的可选结构。本轮不扩展为多分支持久化管理器。

## Testing Decisions

以下测试边界已获用户确认。只验证可观察输入、输出和状态变化，不为私有字段、内部调用顺序或原型实现写镜像测试。

1. **主要边界：牌局应用工作流。** 在现有应用协调层及其调用的公开工作流入口驱动“导入/核对四手 → 开始 → 合法出牌 → 收墩/撤销/重做 → 查询结果 → 修改原始牌面”。观察剩余手牌、当前墩、行动家、赢墩、逐牌标签和定约表版本。必要的新推演行为通过同一高层入口测试，不为每个 UI 控件另造接口。覆盖不完整、重复牌、非法跟牌、将牌/无将、末墩和旧异步回包。
2. **教学边界复用现有请求构建与截图核对测试。** 对比只勾两家和全勾四家的最终请求；检查暗手与 DDS 答案不泄露，截图仍需核对，未提供的信息不被补成已知。沿用 ScreenshotReviewWorkflowTests、DeclarerPlanRequestBuilderTests 与 KeyPlayAnalysisTests 的先例。
3. **真实 DDS 边界复用现有求解集成测试。** 使用可独立验证的固定牌例测试逐牌结果、部分墩、防守方行动和五种定约花色；增加原始 20 格定约表及庄位差异、`—`、满贯边界。沿用 DoubleDummyVerificationTests 和 DoubleDummySolverIntegrationTests。假求解器适合工作流竞态测试，不能替代真实 DDS 数值验证；缺少 helper 时跳过不能算通过。
4. **Runtime 边界复用现有目录、偏好与请求客户端测试。** 覆盖候选失效继续搜索、找不到时路径提示、旧 Sol 偏好迁移、支持档位完整呈现、不支持档位不可提交，以及实际请求携带 6.1 Sol 或 Astra Ultra。沿用 CodexRuntimeModelCatalogTests、CodexModelSelectionPreferencesTests、CodexModelSettingsTests 与 CodexTeachingServiceRequestTests。仅发现逻辑如需新增注入点，将文件发现与运行时探测放在一个适配边界，避免分散到界面。
5. **兼容性边界复用保存记录测试。** 旧记录能读取，原始与剩余手牌不会相互覆盖，冲突 DDS 数据不被静默当成共享事实。沿用 ReviewSessionArchiveTests。
6. **实际 Mac 应用验收。** 在打包应用核对 A 角落小表、连续牌点密度、开始入口、各家点击与标签对齐、展开长叫牌、定约表打开关闭、小窗口可用性。实际执行一次导入复用、真实 DDS 推演及 Runtime 搜索/恢复；在运行时支持时提交一次 Astra Ultra 教学并核实请求身份。原型截图、浏览器交互、mock 请求通过均不等于原生应用验收或证明模型教学质量更好。

## Out of Scope

- 自动替其他玩家出牌、联网对战或从不完整手牌猜测隐藏牌。
- 要求用户录入完整实际牌局历史；自动识别整段打牌视频。
- 品牌、整页布局、现有叫牌语义或教学模式的全面重新设计。
- 实现未被选中的本轮 B/C 布局。
- 多分支推演树、跨设备同步、自动评估模型强弱或保证 Astra Ultra 效果更好。
- 将模拟 DDS 数值或 HTML 原型直接作为产品求解与验收证据。
- 新增账号凭据管理、购买额度或绕过 Runtime 能力限制。
