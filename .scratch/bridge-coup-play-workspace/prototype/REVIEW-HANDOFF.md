# 原型评审交回原会话

2026-10-02。Status: prototype direction accepted。下一步由原会话继续 spec 与 `absurdwall/bridge-coup` GitHub issue；本次未开展生产实现或发布规格／issue。

## 用户已确认

- 本轮叫牌布局 **A 角落小表**。用户说“这个小表我觉得很好看，我很喜欢”。B/C 不再作为待选方向；沿用既有已接受四家围桌，不重开历史原型方向。
- 整体原型与用户预期接近；最终对当前方向表示“可以可以，这么着，嗯，可以”。
- 手牌呈现应接近当前 app 的连续牌点（如 AKQJ10），避免逐张独立牌片的感觉、过大的牌点间距与各家过宽的容器。小牌桌上紧凑四家有价值，但可以稍微放宽一点。
- **先点击“开始自主推演”，再逐家点合法牌**的操作入口可以接受。开启逐牌结果后为标签增加少量高度，并不改变四家布局或由软件自动代打。

## 最终原型形态

- HTML 牌区由最早 220 px／撑满网格，先缩至 136 px，再按最后“一丢丢”放宽到 **144 px**；这是原型中的最终密度参考，产品 spec 应保留视觉意图并结合原生字号／窗口约束处理。
- 关闭结果：牌点按字符宽度连续排列，间隔为零；开启结果：每张当前合法牌下显示独立模拟结果，仅留标签必需的小宽度。没有整体结果替代或二级比较入口。
- 中央当前墩、当前行动家、跟牌约束、双方已赢墩均可操作演示。
- 完整四手是推演前提，教学继续按独立勾选；两手状态仍可使用教学入口。
- 原始四手定约表按 ♠♥♦♣NT 行、北南东西列展示完整定约或 —；出牌不变，改原始牌面失效。
- 开始前的两处提示改为明确“点击开始自主推演后可点牌”。

## 继续保留为候选的细节

当前原型提供四张后手动收墩、撤销／重做／重走。用户没有单独回答先前的收墩方式选择卡，也没有逐项确定这些按钮的详细行为。不要将整体认可夸大为这些细节逐项确认；原会话整理 spec 时可作为建议默认值或有界待定项处理，无需再开一轮整体布局比较。

Runtime 自动发现与模型／effort 能力目录仍以 `../grill-decisions.md` 为已确认需求，未在此原型真实实现。所有 DDS 与教学回执为模拟；用户对布局的认可不构成真实求解或生产 app 验收。
